# Session 02 - NFL vertical slice, part 1 (Milestone 3) - 2026-10-05

## Status at start
- Foundation (session 01) pushed by owner via the GitHub website; CI workflow
  and dot-files created manually on GitHub.
- 100 tests passing in the sandbox.

## Work completed
- Verified nflverse `games.csv` against the official schedules dictionary and
  the live file (7,548 games, 1999-2026). Key facts recorded in the adapter
  docstring: home-positive spread sign, Eastern kickoff times, undocumented
  line source, no license file, post-game columns.
- `sources/nflverse.py`: adapter with sign conversion, UTC kickoffs,
  franchise mapping (STL/LA->LAR, SD->LAC, OAK->LV), conservative timestamps
  when kickoff time is unknown (1999 only), strict validation.
- `ingest/nfl_schedules.py`: games + append-only results; links to games
  created by other sources; score corrections supersede, never overwrite;
  backfill vs live availability.
- `models/nfl_ratings.py`: weighted ridge ratings baseline with uncertainty.
- `backtest/metrics.py`, `backtest/nfl_walkforward.py`: locked-split
  walk-forward evaluation; betting at the close with recorded odds only.
- CLI: `edge ingest nfl-schedules`, `edge backtest nfl`.
- Fixed: logs now go to stderr so command output stays machine-readable.
- Docs: model methodology, backtest results, data sources, architecture.

## Results (real data; see docs/results/2026-10-05-nfl-baseline-backtest.md)
- Test 2023-25: margin MAE model 10.32 vs market 9.79; moneyline log loss
  0.640 vs 0.608 (home-rate baseline 0.688).
- Spread bets at the close, test: 310-351-16, ROI -9.8% (90% CI -15.7 to -3.8).
- Market-informed weight fitted on validation: model coefficient -0.14
  (SE 0.18). Weight left null; no official plays possible from this model.
- Conclusion: no edge. Expected for a scores-only baseline.

## Known limitations
- Lines from nflverse are closing lines of undocumented origin; no
  decision-time prices before our own odds recording starts.
- Normal margin distribution ignores key numbers.
- Backtest reads normalized source records directly; predictions are not yet
  persisted to the `predictions` table.
